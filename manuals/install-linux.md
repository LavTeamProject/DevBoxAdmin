# Установка Service Admin на Linux (со скриншотами)

Руководство проверено **на настоящей Ubuntu 24.04 (arm64) в виртуальной машине**, без экрана (как сервер). Скриншоты — панель, работающая в этой системе,
снятая с другого компьютера через SSH-туннель. Панель сама на русском, язык переключается кнопками **RU / EN** в шапке.

**Что получится:** панель на `http://127.0.0.1:8765` (доступна только с этого компьютера), служба systemd пользователя, которая стартует при загрузке.

**Нужно:** Ubuntu 22.04 / 24.04 или Debian 12+, arm64 или x86_64, `curl`, `tar`, `openssh-client`; **права root не нужны** для самой панели
(root понадобится только для установки пакетов apt и для необязательного «помощника подтверждений», см. ниже).

---

## Способ 1. Одна команда (рекомендуется)

```bash
curl -fsSL https://raw.githubusercontent.com/LavTeamProject/DevBoxAdmin/main/get.sh | bash
```

Скрипт скачает исходники в `~/.service-admin/app`, **свой Python 3.12** (с проверкой контрольной суммы — системный Python не нужен, подходит и Ubuntu 22.04),
поставит службу `service-admin.service` (systemd, пользователь) и включит `linger` (старт при загрузке без входа). Повторный запуск = обновление.
Закрепить версию: `SA_REF=<тег или коммит> SA_SHA256=<сумма>` перед `bash`.

## Способ 2. Пакет .deb

Для Ubuntu 24.04 / Debian 13 (системный Python 3.11+). Исходники лежат в `/opt/service-admin` — владелец root (так безопаснее для «помощника подтверждений»).

```bash
sudo apt install ./service-admin_0.1.0_all.deb
service-admin-setup        # служба для ВАШЕГО пользователя на системном Python
```

Собрать пакет самому: `packaging/deb/build.sh` (нужен `dpkg-deb`).

## Открыть панель

* **С экраном:** откройте `http://127.0.0.1:8765` в браузере (или ярлык «Service Admin» в меню приложений).
* **Сервер без экрана:** с вашего компьютера пробросьте порт и откройте адрес у себя:
  ```bash
  ssh -N -L 8765:127.0.0.1:8765 пользователь@сервер
  ```
  Панель **не слушает сеть** — только `127.0.0.1`; удалённый доступ — только SSH-туннелем.

## Шаг 1. «Подготовка системы»

Панель показывает, чего не хватает: компилятор, `make`, `git`, `curl`. Кнопка **«Поставить»**:

* **с экраном** — системное окно авторизации (polkit) спросит пароль администратора, пакеты `build-essential git curl` ставятся задачей (вкладка «Процессы»);
* **без экрана** — панель **не принимает пароль**: она откроет вкладку «Терминал» с готовой командой `sudo /usr/bin/apt-get install -y build-essential git curl`;
  пароль вы вводите в терминале сами (панель его не видит).

## Шаг 2. Профили, пакеты, службы

* **Профили установки** — наборы: «Фундамент» (git, curl, компилятор, Python, jq, ripgrep, fzf, gh…), Backend, Flutter, Контейнеры (Docker). Профиль ставится **одной командой apt**; до и после делается снимок.
* **Пакеты и сервисы** — службы systemd (пользователя и системные), пакеты apt, поиск, рекомендации. Системные службы и установка пакетов требуют прав администратора (тот же порядок: окно polkit или терминал).
* ⚠️ Профиль «Контейнеры» ставит Docker: **членство пользователя в группе `docker` равно root-доступу** — тогда канал подтверждения агентов отключается (см. `connect-ai-agent-linux.md`).

## Шаг 3. Снимки и аудит

**Снимки** запоминают установленные пакеты apt и версии языков (до и после любого изменения — для сравнения). **Аудит** — журнал всего, что делала панель,
с указанием, **кто** инициировал (пользователь / агент / система). Секреты в журнал не попадают.

## Удаление

```bash
~/.service-admin/app/uninstall-linux.sh      # способ 1  (или /opt/service-admin/uninstall-linux.sh для .deb)
rm -rf ~/.service-admin                      # данные (необязательно)
```

## Если что-то пошло не так

| Симптом | Что делать |
|---|---|
| `curl … 404` | репозиторий ещё не опубликован или закрыт; скачайте архив вручную и запустите `./install-linux.sh` |
| «systemd пользователя недоступен» | сессия без шины пользователя: выполните вход по ssh заново или запустите `sudo loginctl enable-linger $USER`; запасной режим — сервер в фоне без автозапуска |
| порт 8765 занят | `ss -ltnp \| grep 8765`; другой порт: `python3 server.py --port 8766` |
| страница пустая через туннель | проверьте, что туннель на `127.0.0.1:8765`, а адрес в браузере `http://127.0.0.1:…` (панель проверяет заголовок Host) |
| журнал службы | `journalctl --user -u service-admin -n 100` или `~/.service-admin/logs/server.err` |
