# CI-раннеры по требованию на Linux (QEMU)

Те же понятия, что в `ci-runners.md` (источник с токеном доступа, самотест, раннер на одно задание). **Отличается гипервизор:** на Linux панель использует **QEMU без root**
(на macOS — tart). Проверено на Ubuntu 24.04 (arm64): основа, изоляция сети и **самотест CI на временной Gitea** — `SELFTEST PASSED`.

![Виртуальные машины и CI-раннеры](img/lx-vms.jpg)

## Что нужно

* Пакеты: `qemu-system-arm` (arm64) или `qemu-system-x86` (x86_64), `qemu-utils`, `qemu-efi-aarch64` (только arm64), `sshpass`, `openssh-client`. На странице «Виртуальные машины» кнопка **«Установить пакеты QEMU»**.
* **Доступ к KVM:** добавьте пользователя в группу `kvm` (`sudo usermod -aG kvm $USER`, перелогиньтесь). **Без KVM** ВМ работают программной эмуляцией — в десятки раз медленнее (на странице горит метка **TCG**); годится для проверки, не для работы.
* Свободное место: ~4 ГБ на образ и основу.

## Шаги

1. **«Создать основу (Ubuntu)…»** — панель скачает официальный облачный образ Ubuntu (проверяет sha256), настроит гостя через cloud-init (без сети!) и выключит. Вход в гостя — **по ключу**, пароля нет, ключ хоста гостя закреплён.
2. **«Установить в ВМ…»** (рецепты): `node` (качается на хосте, гостю интернет не нужен), `build` (build-essential через apt — **единственный** рецепт с выходом гостя в интернет).
3. Дальше — как на macOS: **«Установить файлы»** раннера (Linux-сборки `gitea-runner` и `actions/runner`), **«Раннер в ВМ…»**, **«Добавить источник…»** с токеном, **«Проверить»**, **«Самотест CI…»** или **«Раннер по требованию…»**.

## Изоляция сети — строже, чем на macOS

Гость раннера **не видит ни интернет, ни вашу локальную сеть, ни сам компьютер** (адрес `10.0.2.2`): достижим **один адрес — сервер CI** (панель пробрасывает его на 10.0.2.100).
Следствия: workflow, которым нужен интернет (`actions/checkout` с внешнего адреса, `npm install`, `apt`), в этом режиме не заработают — подготовьте нужное в **основе** (рецепт `build`, свои пакеты) или
используйте зеркало на самом сервере CI. Режима «без изоляции» для раннеров на Linux **нет** (иначе гость дотянулся бы до API панели на 127.0.0.1).

## Безопасность в двух словах

* Раннер одноразовый (`--ephemeral`), ВМ удаляется всегда; токен — в файл гостя через stdin, из вывода вырезается.
* **Не подключайте публичный репозиторий, куда принимают pull request от посторонних**: код из PR выполнится на раннере и увидит секреты задания (но не вашу сеть).
* Запуск раннеров агентам — только L3 и только с подтверждением человека (`connect-ai-agent-linux.md`).
