## A. Самое важное (без внешних аккаунтов)

### A1. Диалог подтверждения для ИИ-агента — ✅ сделано 2026-10-13 (Одобрить / Отклонить / таймаут)
Зачем: это главная защита Фазы 4. В ВМ диалог показывался, но на него никто не нажимал.
1. Запустите панель, откройте **«Подключение агентов»** (`#connect`).
2. Зарегистрируйте агента: имя `test`, уровень **L2**. Скопируйте путь файла секрета/команду (секрет не показывается — это нормально).
3. В терминале (подставьте id агента, он виден в таблице, вида `a1b2c3`):
   `./service-admin --agent <id> plan --op snapshot.create --param label=check1` → в ответе будет `plan_id` (вида `p…`).
4. На странице **«Подключение агентов»** в очереди запросов появился план (вверху меню — счётчик ожидающих). Нажмите **«Одобрить»**
   (панель переспросит) → появится **системный диалог macOS** с именем агента, операцией и параметрами (кнопка по умолчанию — «Отклонить»).
5. **В системном диалоге нажмите «Одобрить»** → затем `./service-admin --agent <id> execute <plan_id>` → ожидаем `done`/job; на странице «Снимки» появился снимок `check1`.
6. Повторите шаги 3–4 с новым планом (`label=check2`) и **в системном диалоге нажмите «Отклонить»** → `execute` должен отказать (`plan.rejected`).
7. Ещё раз новый план, нажмите «Одобрить» в панели, а в системном диалоге **ничего не нажимайте 2 минуты** → план `rejected` по таймауту (110 с).
Прислать: «A1: ок» или что пошло не так (текст диалога, что ответил `execute`).

## B. Нужны ваши аккаунты/репозитории

### B1. Раннер по требованию на **вашей** Gitea (`https://git.example.com`) ⭐ — теперь проще: нужен только токен доступа
Вам нужно **один раз создать токен доступа** (репозитории и workflow панель создаёт сама):
1. В Gitea: аватар → **Settings → Applications → Generate New Token**. Имя `service-admin`. Права (scopes):
   `write:repository`, `write:organization`, `write:user` и, если хотите область «весь сервер» (instance), ещё `write:admin`
   (токен должен принадлежать администратору Gitea). Для области «организация» достаточно первых трёх.
2. Убедитесь, что в Gitea включены Actions (`[actions] ENABLED = true`).
3. (Подробно: **`manuals/ci-runners.md`**.) В панели `#vms` → **CI-раннеры → «Добавить источник…»**: система `gitea`, адрес `https://git.example.com`, область `instance` или
   `org` (+ имя организации), название `Lab`, тип токена **`api`**, вставьте токен. (Токен хранится только в файле 0600 на этом Mac.)
4. У источника: **«Проверить»** → «Подключение работает…», затем **«Самотест CI…»** → выберите ВМ-основу `runner-base` и введите название источника.
Ожидаем: журнал заканчивается `SELFTEST PASSED`; тестовый репозиторий и `ci-…` ВМ удалены; в Gitea нет лишних раннеров.
Область `repo` для самотеста не подходит (он не коммитит в ваш репозиторий) — для неё доступна кнопка «Раннер по требованию…».
Прислать: «B1: ок» или кусок журнала (токенов в нём быть не должно).

### B3. Резервные копии на внешний диск
1. Подключите внешний диск; на странице **«Резервные копии»** укажите папку на диске (`/Volumes/<диск>/…`), запустите копию.
2. Ожидаем: копия создана и проверена (статус «ок»).
3. **Отключите диск** и запустите копию снова → ожидаем понятную ошибку «назначение недоступно», ничего не сломалось.
4. Верните диск → копия снова проходит.
Прислать: «B3: ок» или текст ошибки.

### B4. Git: push/fetch в настоящий remote
Нужен тестовый репозиторий (можно тот же `ci-lab`) и ваша обычная авторизация git (SSH-ключ или credential helper).
1. На странице **Проекты** добавьте клон тестового репозитория в реестр.
2. Внесите правку → «Add/Commit» → **Push** → проверьте, что коммит появился на сервере; потом **Fetch/Pull**.
Ожидаем: работает без запроса пароля в терминале панели; при отсутствии доступа — понятная ошибка, а не зависание.
Прислать: «B4: ок» или ошибку.

### B5. GitHub Actions из панели (workflow_dispatch)
Нужен репозиторий GitHub с workflow, у которого `on: workflow_dispatch`, и `gh auth login`.
1. На странице проекта → блок GitHub → «Запустить workflow» → введите имя проекта для подтверждения.
Ожидаем: запуск виден в Actions на GitHub. Прислать: «B5: ок/не ок».

### B6. Установка пакета «по-настоящему» через панель/агента
1. В панели (**Пакеты**) установите **лёгкий** пакет, которого у вас нет (например `jq`), затем удалите.
2. Либо через агента L2 (см. A1): `plan --op package.install --param name=jq --param type=formula` → одобрить → `execute`.
Ожидаем: пакет появился/исчез в `brew list`, в журнале аудита (`#audit`) есть запись.
Прислать: «B6: ок» или ошибку.

### C2. Ограничение сети ВМ (softnet) — ✅ сделано и проверено
Вы выставили права `softnet` — изоляция включена и проверена (гость видит только сервер CI; роутер и устройства LAN недоступны).
Что теперь учитывать: сервер CI должен быть доступен гостю по **LAN-адресу хоста/сервера** (`192.168.64.1` при softnet не работает);
разрешается один адрес (`/32`) из URL источника. Откат (если нужен): `sudo chmod u-s ~/.local/bin/softnet` или `rm ~/.local/bin/softnet` —
тогда изоляция выключится сама, а в журнале job появится предупреждение.

### C3. Образ ВМ с git и Node — ✅ уже сделан мной
ВМ `runner-base` (в списке `#vms`; остановлена) содержит git, Node 24 и файлы gitea-runner; на ней проверен настоящий `actions/checkout@v4`.
Используйте её как «ВМ-основу» в «Раннер по требованию…». Если для ваших workflow нужны другие инструменты (Xcode, Flutter и т. п.) —
скажите, что именно, и я добавлю в основу. ⚠️ Если на вашем Mac включён VPN, у гостя нет интернета (см. `docs/unverified.md`, «Окружение»).
