## 2. Принципы (как в хороших веб-панелях: ISPmanager, Plesk, cPanel)
1. **Одна задача — одно место.** Настройка живёт на одной странице; с остальных — ссылка. Никаких копий.
2. **Меню по объектам и задачам**, без групп из одного пункта.
3. **Единый шаблон страницы:** заголовок + статус-чипы + главное действие; вкладки; «список → карточка»; единое подтверждение опасного; **пустые состояния и блоки ошибок — часть шаблона** («что сделать дальше», «Повторить»).
4. **Вход по задаче:** «Начало работы» (единый первый запуск: подготовка системы → наборы инструментов). Без ролей — категории задают группы меню.
5. **Честные названия:** страница называется тем, что умеет (если отката нет — не «откат»).
6. **Сбой одной части не ломает страницу.**
7. **Ослабляющие защиту действия видны и объяснены.**

## 4. Шаблон страницы
- Шапка: название · статус-чипы · главное действие. Вкладки не больше шести, одна по умолчанию.
- Таблицы: одинаковые колонки («имя · версия · откуда · размер · действия»), фильтры сверху.
- Блоки грузятся независимо; ошибка блока — рамка с текстом и «Повторить»; пустое состояние — с кнопкой следующего шага.
- Единое окно подтверждения опасного действия со списком затронутого.
- Реализуется на ванильном JS (готовые помощники `roBanner`, `kvList`, `chipList` уже есть) с соблюдением правила «`load()` отдельно от `render()`» — иначе ломается смена языка. Подвкладки `docker.js` и `connect.js` переводятся на один общий механизм.

## 5. «Начало работы» и наборы инструментов
Без ролей. «Начало работы» — две вкладки: **подготовка системы** (Homebrew, git, Python панели) и **наборы инструментов** (бывш. «Профили установки») — плоский список готовых наборов: Основа, ИИ-агенты, Flutter, iOS, Backend (общее), Backend: PHP/Laravel, Node.js, Python, Go, Web. У набора — чек-лист «готово N из M», «Поставить» у пункта и «Поставить всё недостающее» (с подтверждением списком). Каталог `profiles.py` (этап U4a) уже переписан: каждый инструмент описан один раз; у БД-сервисов есть «запущено/остановлено»; состояния пункта: установить · вручную · позже (большая загрузка) · нужен администратор · нужно согласие (лицензия Android SDK; лицензию Xcode и Apple ID человек делает руками, пароль панель не вводит). Определение Flutter — по файлам: панель **не запускает `flutter --version`/`flutter doctor`**. Ограничения, которые видно в интерфейсе: одновременно идёт одна установка набора; cask-приложения могут вызвать окно пароля администратора; GUI-программы и ручные пункты детектор не видит.

## 6. Сквозное
- **Центр внимания:** блок на «Обзоре» и значок в шапке: план ждёт одобрения, есть обновления, сервис упал, мало места, токен истекает. Данные — **из отдельного кэшируемого запроса** (список обновлений brew медленный и требует сети), а не из двухсекундного опроса дашборда.
- **Глоссарий RU/EN:** одно слово — одно понятие («план», «оператор», «агент», «сервис», «снимок», «копия»).
- **Адаптивность и доступность:** фокус, контраст, клавиатура; узкий экран (панель открывают с телефона через туннель).
- **Linux:** меню строится по возможностям; пункты macOS-only скрыты, в чек-листах нет Xcode-пунктов.

- **Есть в Homebrew, у нас нет** (проверено по локальным формулам): Neo4j, etcd, Temporal, Tomcat, phpMyAdmin, Podman, .NET, Erlang, Zig, mongosh; приложения-cask: ClickHouse, Consul, pgAdmin 4, DbGate, MongoDB Compass, TablePlus. **Нет в Homebrew** (нужен tap или другой способ): Elasticsearch, Qdrant, Typesense, FrankenPHP, n8n, Adminer, Redis Commander.
- **Предложение:** добавить в каталог ~12 карточек «Инструменты баз данных» (phpMyAdmin, pgAdmin 4, DbGate, TablePlus, mongosh, Compass) и «Инфраструктура» (etcd, Consul, Temporal, Neo4j, ClickHouse, Tomcat, Podman) — это данные каталога, цена низкая. И готовые **наборы сервисов** («Laravel»: nginx + php + MySQL + Redis + Mailpit; «Node»: MongoDB/PostgreSQL + Redis; «Python»: PostgreSQL + Redis + RabbitMQ) с кнопкой «запустить всё».

**Функции (что стоит взять, по пользе/цене):**
1. **Одинаковая страница объекта: «Версии · Настройки · Журнал».** У них модуль = версии + сервис + конфиг + лог в одной раскладке. У нас страницы языков, сервисов и Docker устроены по-разному — это главная идея для U3/U5 (низкая–средняя цена, высокая польза).
2. **Группы запуска («запустить всё»):** набор сервисов, стартующих/останавливающихся вместе, поверх `brew services` (средняя цена).
3. **Порты:** вкладка «кто слушает какой порт» и конфликты (только чтение; без «убить процесс») (низкая цена).
4. **Локальные домены и HTTPS без правки `/etc/hosts`:** встроенный DNS + mkcert + обратный прокси: «добавить сайт: папка или порт → https://имя.test». У нас — Herd (только PHP) и ручная правка hosts. Основа для U5 «Сайты и домены»: dnsmasq (уже в каталоге) + mkcert + nginx/Caddy (высокая цена, высокая польза).
5. **Версия по проекту без менеджера:** подсказка «проект просит Node 20 (`.nvmrc`/`.node-version`/`.tool-versions`), активна 26» + кнопка «поставить / сделать основной» (низкая цена).
6. **Быстрые действия в шапке** (у них плавающая кнопка/трей): запустить/остановить группу, открыть сайт (низкая цена).
- Не берём: инструменты вроде регулярок и хешей, собственный DNS/FTP-сервер.
- Наше преимущество, которое нужно беречь: шлюз ИИ-агентов с подтверждениями, удалённые операторы (Telegram/API), ВМ и раннеры, Linux. У FlyEnv ИИ — это MCP-сервер («скажи ИИ, что запустить»), без подтверждений человеком.

**Дизайн.** Сайт: чередование «текст — скриншот», нумерованные шаги, сетка логотипов, переключатель языков; в приложении — боковая панель модулей, список версий с метками «Installed / Install», панель «Start all», настройки внешнего вида. Выводы: мы уже близки (тёмная тема, боковое меню, логотипы продуктов); не хватает **единой раскладки объекта**, **группы запуска «запустить всё»** и **понятной страницы «что установлено / что можно поставить»** в одном виде.

## 11. Что показал обзор похожих продуктов
- **FlyEnv** (BSD-2, macOS/Windows/Linux) — самый близкий аналог: версии рантаймов, веб-серверы и БД, локальные домены и HTTPS, сервисы проекта, в одном интерфейсе без Docker. **Laravel Herd** — эталон для PHP/Laravel (сайты, PHP-настройки, nginx, dnsmasq, Node), закрытый. **DevPod** — окружения в контейнерах; **Flox/Devbox/mise** — версии и пакеты на проект, без панели. У нас отличие: **шлюз ИИ-агентов с подтверждениями**, удалённые операторы (Telegram/API), Linux, ВМ и CI-раннеры — этого нет ни у одного из них; а вот «версии + сервисы + домены в одном месте» стоит перенять у FlyEnv/Herd.
- **ISPmanager, Cockpit, Coolify** (приёмы): после входа — **обзор**, затем постоянное левое меню (не прячется и не появляется — «прыгающая» панель раздражает); в ISPmanager меню имеет уровни «все / основные / избранные / частые» и поиск; Cockpit отделил обзоры от настроек конкретного хоста; Coolify строит иерархию «сервер → проект → окружение → ресурс» и вкладки на объекте. Вывод для нас: обзор + стабильное меню + вкладки на странице объекта; **избранное и частые** — возможная замена откладываемым поиску и «профилю интерфейса».
- **Версии:** `uv python list --all-versions` / `uv python install 3.12.3`, `nvm ls-remote`, `fvm releases` / `fvm install`, `mise ls-remote node` / `mise install node@20` — у менеджеров версий есть списки «всех» версий; у Homebrew — только версионные формулы.

## 10. Открытые вопросы
1. **«Старые версии» (Node и др.):** Homebrew даёт только `node@N` поддерживаемых версий. Согласны? (Python сейчас уже ставится через `uv`, Flutter — через FVM.)
