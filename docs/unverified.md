## Окружение, о котором надо знать

- **Диск ВМ tart (Tahoe) не расширить внутри гостя:** раздел восстановления стоит перед свободным местом, SIP не даёт его удалить, `diskutil apfs resizeContainer` отвечает «-69519». Поэтому том гостя остаётся ~44 ГБ, свободно ~18 ГБ, и диалог Apple для Command Line Tools отказывает (нужно 24,27 ГБ) — обход: `softwareupdate`.
- **Нажатие кнопок внутри окна ВМ:** окно ВМ — процесс `tart` без регистрации как приложение, управление экраном (computer use) к нему доступа не даёт; клики по диалогам гостя выполняет владелец. Окно ВМ создаётся только при запуске `~/.local/bin/tart run <vm>` в обычном Terminal пользователя.

- **Гость ВМ не имеет интернета при включённом VPN на хосте** (маршрут по умолчанию через `utun…`): NAT tart/vmnet не пересылает трафик через туннель.
  Локальная сеть и мост `192.168.64.1` при этом работают (раннер связывается с Gitea на хосте). Проверить: в госте `curl https://example.com`
  не отвечает; выключите VPN — отвечает. Для workflow из интернета: отключайте VPN на время запуска раннера (или используйте зеркало действий, как в тесте).

## Мелкие замечания (не блокируют)

- `vm.restore` не атомарен: если удаление ВМ прошло, а переименование нет, копия снимка остаётся как `<начало>-restoring-…`, а журнал сообщает точную команду `tart rename …` для завершения вручную. Снимки старого формата (`<имя>-snap-<время>`, до исправления хеша) не восстанавливаются.

- Нативные `prompt()`/`confirm()` остаются для обычного ввода (имена, подтверждения); токены вводятся в диалоге с полем-паролем (`askSecret`).

## Docker для агентов (list_containers / docker.container_control / cancel_job)
- Проверено на подменах (удалённый контекст → `docker.remote_context`, чужая задача → `plan.job_not_yours`); реальные start/stop контейнера через план с настоящим диалогом на рабочем Mac не гонялись.

## Рецепты подготовки ВМ (`vm.recipe`)
- `node`: проверен на копии `clean-mac` (скачивание на хост, sha256, заливка, `node --version` в госте, ВМ остановлена и удалена).
- `clt`: проверен только путь отказа — у гостя нет интернета, пока на хосте включён VPN (ясная ошибка, ВМ остановлена). **Полная установка проверена** в чистой ВМ при выключенном VPN: Command Line Tools for Xcode 26.6 поставились за ~3,7 мин, `xcode-select -p` = `/Library/Developer/CommandLineTools`, `git` и `clang` в госте работают, ВМ остановлена.
- Xcode, Flutter, Android Studio рецептами не автоматизируются (Apple ID / лицензии) — осознанное исключение.
- Целостность Node.js: sha256 берётся с того же nodejs.org (подпись `SHASUMS256.txt.asc` не проверяется); файл исполняется только внутри одноразовой гостевой ВМ. Если ВМ станет основой для CI, имеет смысл закрепить версии и суммы в репозитории.

- HTTPS-инстанс Gitea 1.27.2 владельца: проверено только чтение — источник области org добавлен по токену доступа, «Проверить» вернул пользователя и список раннеров (1). Самотест и раннер по требованию на этом сервере НЕ запускались (по решению владельца: «Только Проверить»).

- `get.sh` (установка одной командой): скачивание/распаковка/проверка суммы/отказ при неверной сумме и плохом `SA_REF` проверены локально на архиве `git archive` (без установки). **Полная цепочка проверена в чистой ВМ (macOS 26.6, vanilla):** `curl … | zsh` с GitHub → исходники в `~/.service-admin/app` → `install.sh` (свой Python 3.12, приложение в /Applications, LaunchAgent) → панель отвечает 200 на `127.0.0.1:8765`.
